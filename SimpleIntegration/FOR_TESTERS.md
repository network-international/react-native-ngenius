# React Native Tokenization POC - QA Testing Guide

Use the SHA and artifact names in the accompanying BUILD_INFO.txt. Branch: NINGG-34386 (PR #75). SDK 3.2.9.

6 Nov update: use Add Card for DEV and UAT for now, per Hossam, and wait for the new deployed version. Record the actual environment and deployment/build when retesting. This guidance does not establish a successful live Add Card result. Session creation/lookup/validation, final selected-token persistence, collected-consent deployment and physical wallet E2E remain pending.

Current UI source uses a compact hosted-preview-style panel, green shield, NI footer and optional title/subtitle. Card and wallet rows lead with the masked funding number, with `Expires MM/YY` on its own line and a separate Card/Wallet source tag. The first usable method is selected by default; the blue radio is separate from green backend-reported Verified status. NI PayPage SVG artwork, native Card Back, animated loading/retry and the configurable return control remain. Use a build matching the current PR SHA; earlier screenshots/builds may show the retired checkbox UI. Offline screenshots and simulated selection responses are demo/mock evidence.

1. Android: install the SHA-named APK with `adb install -r <apk>`, then open SimpleIntegration. It includes the JS bundle; Metro is not needed.
2. iOS Simulator: extract the SHA-named ZIP, run `xcrun simctl install booted <app>`, then `xcrun simctl launch booted org.reactjs.native.example.SimpleIntegration`. This app cannot be installed on a physical iPhone. A device build requires existing signing; no Team/profile/certificates were changed.
3. Open **Tokenization sandbox QA**. Obtain a fresh short-lived TOKENIZATION_SDK Access-Token through the approved secure flow, paste it into the password input and tap **Open sandbox tokenization**. Do not put an API key in the app. The token stays in memory, clears on close, and the provider rejects it after five minutes. Paste a fresh token for every new session.
4. Sandbox host: `https://paypage-sandbox.platform.network.ae`. Live QA always uses **skipConsent=true** and outlet `a6b162e9-7a75-403c-b238-6303b2df455c`. Saved Tokens calls `/tokens?consentOff=true`. HTTP 200 with an empty list and no tncUrl is valid. No consent block should appear. Use Retry for load errors; 401/403 requires a fresh authorized token.
5. For UI checks without credentials, enable **UI preview (no network)**. Check default/merchant theme, EN/FR/AR, Arabic RTL, skip-consent ON/OFF, click-to-agree notice, legal-link navigation, Saving terms expansion and close/reopen. There is no consent checkbox or “loaded” text after successful list retrieval. Preview responses are fixtures and do not prove sandbox E2E.

Card: Add Card opens a native-only form on both platforms. Check invalid/expired fields, cancel, then tokenization with approved sandbox test data and a fresh Access-Token. PAN/CVV must not appear in JS, logs or screenshots. Preview opens the same form but refuses submission before HTTP. VERIFIED refreshes Saved Tokens; FAILED is an error; AWAIT_3DS is pending and does not run Card 3DS in Drop 1.

Wallets: Google Pay returns the original encrypted token; Apple Pay uses a separate native encrypted paymentData capture. Both POST `/wallets` with the confirmed consentData. Enter approved PUBLIC UAT configuration as JSON with `googlePay` / `applePay` objects. Check availability, open/cancel, one submission, VERIFIED refresh, AWAIT_3DS pending and FAILED error. A real wallet E2E requires a physical Android/iPhone, valid UAT config and, for Apple Pay, merchant entitlements/signing. No real wallet E2E has been established by simulator builds.

Consent: with skipConsent=false, each actionable Add Card/Wallet click prepares COLLECTED with a fresh UTC acceptance timestamp for that attempt. Selecting an existing method, cancelling, opening T&C/Privacy Policy and toggling Saving terms must not accept consent. Missing/invalid T&C URLs leave plain text; a Privacy Policy link appears only for a valid configured HTTP(S) URL. The recurring NI storage wording remains accessible under Saving terms. With skipConsent=true, the whole notice is absent and data is NOT_COLLECTED with merchantSelectedSkipConsent=true. Live sandbox remains skipConsent=true; COLLECTED UI/contract checks use offline preview while consentOff=false deployment is pending. No IP, server timestamp or tracking identifiers are sent by the SDK. Device screen dimensions are React Native logical screen units.

Optional order display: check absent details (no invented amount/summary), amount only, partial supplied items/fees and a complete summary. It starts collapsed; modeConfig.orderSummaryInitiallyExpanded=true opens it initially. Header total must prefer supplied orderSummary.total, then amount. Money value uses nonnegative integer minor units and accepts digit strings; check AED '3910' as 39.10, a currency with different precision, and invalid/incomplete money omitted. No quantity multiplication, total calculation, guessed currency or FX should occur. Explicit orderDetails must not merge missing fields from legacy order. Check language fallback: supported language prop, orderDetails.language, legacy order.language, then English; region tags resolve to EN/FR/AR.

Configuration: verify modeConfig.labels.pageTitle/pageSubtitle, return-button variants and localized default labels. Privacy Policy is absent without a valid URL. The default security note reads “Card details are sent securely to Network International.” and modeConfig.showSecurityNote=false hides it. The shield/NI footer and Verified badge do not indicate payment completion. Existing PAYMENT exports and native Card entry are unchanged by this chooser update.

Backend-dependent: final consentOff=false deployment and tncUrl behavior. Do not test live consentOff=false in this build. Card 3DS is outside Drop 1.

Defects must include build SHA, device/model, OS, language, theme, steps and expected/actual behavior. Never include PAN, CVV, API key, Access-Token or wallet payload in screenshots, logs or tickets.

Developer build: copy `src/config.example.js` to ignored `src/config.js` (public defaults, credentials blank), install the demo dependencies and run `pod install` from `ios`. The legacy Android demo requires JDK 17 and a modern D8 compiler: set `NI_QA_D8_JAR` to an installed Android Build Tools `lib/d8.jar`, then run `./gradlew -Pandroid.aapt2FromMavenOverride=<installed-build-tools>/aapt2 :app:assembleRelease`. No compiler binary is committed.
